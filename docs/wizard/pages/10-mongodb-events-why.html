10 MongoDB: events collection

Event sourcing — the canonical source of truth for everything that happened

events108 event types
Every state change captured as an immutable event. Primary source for WebSocket real-time updates and audit trail.
eventIdsessionIdseqtypepayload{}timestamp
Read: EventChangeStreamTailer, CheckpointService (replay), all Controllers
Write: EventService — all agents emit via emit(sessionId, type, payload)
Compound unique: {sessionId, seq}
WHY event sourcing? Events provide a complete audit trail of every system action. Sessions and messages could be reconstructed from events alone. This enables time-travel debugging, replay, and full accountability.
WHY not just CRUD? CRUD overwrites state — you lose the "how we got here". With events, you can answer: "What did the reconcile-agent do at 9:03 AM?" and "Which tool calls created this ticket?"
