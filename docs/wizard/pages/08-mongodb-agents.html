8 MongoDB: agents collection

Runtime-configurable agent definitions — no redeployment needed

agents15 documents
Every agent's DNA: system prompt, skills, tool allowlist, role, and enabled flag.
agentIdnamedescriptionsystemPromptskills[]allowedTools[]roleenabled
Read: AgentBootstrapService (startup), AgentLoop, AgentGraphBuilder (routing)
Write: Admin API, AgentController
Index: agentId (primary key only)
WHY MongoDB? Agent definitions stored in MongoDB enable runtime configuration without code changes. You can modify system prompts, add/remove tools from an agent's allowlist, and enable/disable agents — all through the REST API, no redeployment.
WHY not config files? Config files require restart. MongoDB documents can be hot-swapped — the next agent invocation picks up changes immediately.

The 3 Agent Roles

CONTROLLER
Analyzes user intent, picks the best specialist. Fork is discarded after routing decision.
SPECIALIST
13 domain experts. Each has a focused system prompt and restricted tool allowlist. Output is merged to main state.
CHECKER
Validates specialist output. Pass or fail with feedback. Max 3 retries before accepting.
