5 How Agents Communicate

3 distinct mechanisms — none of them use Change Streams

⚠ Key Insight
Change Streams are only used to push events to the browser UI via WebSocket.
Agents never communicate through Change Streams. All agent–to–agent data flows through one of the 3 paths below.
① Intra-Session (In-Memory)
Controller → Specialist → Checker
All three share an AgentState object in JVM memory.

Each agent gets an isolated fork of the state. After execution, only the final text is merged back. Forks are discarded.

No MongoDB reads/writes between controller, specialist, and checker.
controllerState = state.withAgent(ctrl)
  // fork → parse JSON → discard fork

specialistState = state.withAgent(spec)
  // fork → run tools → merge output

checkerState = state.withAgent(chk)
  // fork → pass/fail → discard fork
② Inter-Phase (MongoDB Poll)
Pipeline Phase N → Phase N+1
IntakePipelineService orchestrates phases sequentially on a virtual thread.

After starting a session, it polls MongoDB every 200ms checking session.status for COMPLETED.

Then reads the last assistant message from messages collection and embeds it in the next phase's prompt.
agentLoop.startAsync(sessionId)

// poll every 200ms:
while (status != COMPLETED)
  Thread.sleep(200)
  status = sessionRepo.findById(id)

output = getLastAssistantMsg(id)
seedUserMessage(nextSession, output)
③ Shared DB State (Tools)
Agent A writes → Agent B reads
Tools write domain objects to MongoDB collections. The next agent's context prep or read tools load them as prompt context.

This is indirect communication — agents never address each other, they share state through the database.
Generalist writes:
  create_thread → threads
  create_ticket → tickets

Reconcile reads:
  read_tickets, read_objectives
  + prompt embeds existing threads
🔍 Troubleshooting Checklist
1. Find pipeline: sessions where metadata.pipelineId
2. Check each phase's status: session.status (COMPLETED / FAILED)
3. Read agent output: messages where sessionId, role = assistant
4. Check tool calls: messages where role = tool
5. View event timeline: events where sessionId ordered by seq
6. Check domain state: query threads, tickets by projectId
🔄 What Change Streams Actually Do
EventService.emit() → insert into events collection
→ MongoDB Change Stream detects insert
→ EventChangeStreamTailer receives event
→ JavaClawWebSocketHandler (the only listener)
→ WebSocket push to browser

No agent or pipeline service subscribes.
Pipeline sync = direct MongoDB polling.
