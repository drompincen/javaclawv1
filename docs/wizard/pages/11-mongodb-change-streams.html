WHY Change Streams over Kafka? MongoDB Change Streams eliminate a separate message broker. The database IS the event bus. This reduces infrastructure from 3 systems (app + DB + broker) to 2 (app + DB), while providing the same real-time push semantics.
WHY not polling? Change Streams push events instantly (sub-millisecond latency). Polling would add 200ms+ delay and waste database queries. Change Streams use the MongoDB oplog — zero additional load.
Fallback: If the change stream connection drops, EventChangeStreamTailer automatically switches to polling every 200ms with sequence tracking. When the stream reconnects, it resumes from the last known position. No data loss.
Requires: MongoDB Replica Set (even a single-node replica set works). Change Streams read from the oplog which only exists in replica set mode.
